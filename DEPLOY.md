# Запуск: от репозитория до показа заказчику

Пошагово. Каждый шаг заканчивается проверкой — если она не прошла, дальше идти
бессмысленно, там же написано что делать.

Аккаунтов нужно три: GitHub, Sanity, Cloudflare. Все бесплатные на нашем объёме.
**Пароли и токены никуда мне не присылайте** — они вводятся только в интерфейсах
сервисов и в настройках репозитория.

---

## Две папки, и почти всё делается во второй

```
/Users/diidentikit/otherworldly        ← корень: здесь git
└── site                               ← проект: здесь npm и sanity
```

Команды ниже начинаются с `cd`, чтобы не приходилось помнить, где вы находитесь.
Скопировали строку целиком — она отработает из любого места.

---

## Что где будет жить

| | |
|---|---|
| Код | GitHub, репозиторий `otherworldly` |
| Сайт | Cloudflare Workers → `otherworldly.<ваш-поддомен>.workers.dev` |
| Админка | **`otherworldly.sanity.studio`** — отдельный адрес, хостинг Sanity |
| Тексты и фото | база Sanity, отдельно от кода |

Тильда остаётся жить параллельно и ничего из этого не касается.

**Почему админка отдельно, а не на `/studio`.** Я закладывал её прямо в сайт:
один домен, один вход. Не поместилось. Воркер Cloudflare ограничен 3 МБ,
а со встроенной Студией сборка весит 18,5 МБ — пакет `sanity` тянет 22 МБ сам
по себе. Платный тариф поднимает потолок до 10 МБ, то есть не спасает тоже:
это ограничение не про деньги.

Побочно вышло лучше замысла: правки в админке больше не требуют пересборки
сайта, а Sanity держит Студию бесплатно.

**Почему не GitHub Pages.** Pages раздаёт только статические файлы, а сайт умеет
серверный рендеринг и пересборку страниц по расписанию. Код всё равно лежит
на GitHub; Cloudflare просто берёт его оттуда.

## Шаг 0. Установить зависимости

Обязательно первым: до установки не заработает ни `sanity`, ни сборка.

```bash
cd /Users/diidentikit/otherworldly/site && npm install
```

> **Проверка.** `ls node_modules/.bin/sanity` печатает путь, а не ошибку.

## Шаг 1. Проект Sanity

Без него админку показывать нечего, а на сайте будут демо-данные.

Сначала зарегистрируйтесь на **https://www.sanity.io** — можно через тот же GitHub.

```bash
cd /Users/diidentikit/otherworldly/site && npx sanity login
```

Откроется браузер. Дальше — создать проект вместе с набором данных одной командой:

```bash
cd /Users/diidentikit/otherworldly/site && npx sanity projects create "По-ту-сторонний" --dataset production --dataset-visibility public
```

Команда напечатает **Project ID** — строка вида `a1b2c3d4`. **Сохраните её**,
дальше она нужна несколько раз.

`public` означает «читать может кто угодно». Для публичного сайта это правильно
и избавляет от токена на чтение; писать всё равно смогут только приглашённые.

> **Проверка.** `cd /Users/diidentikit/otherworldly/site && npx sanity projects list`
> показывает ваш проект и тот же ID.

### Локальные ключи

Создайте файл `site/.env.local` — он в `.gitignore` и в репозиторий не попадёт:

```bash
cd /Users/diidentikit/otherworldly/site && cat > .env.local <<'EOF'
NEXT_PUBLIC_SANITY_PROJECT_ID=ВАШ_ID
NEXT_PUBLIC_SANITY_DATASET=production
NEXT_PUBLIC_SITE_URL=http://localhost:3000
EOF
```

Не забудьте заменить `ВАШ_ID` внутри файла — команда впишет его буквально.

### Проверить, что связка работает

Сайт и админка запускаются отдельно, разными командами и на разных портах.

```bash
cd /Users/diidentikit/otherworldly/site && npm run dev
```

> **Проверка.** http://localhost:3000 открывается и показывает демо-данные.
> Если ошибка про `projectId` — переменные читаются только при старте:
> остановите `Ctrl+C` и запустите заново.

Админка локально — во втором окне терминала:

```bash
cd /Users/diidentikit/otherworldly/site && npx sanity dev
```

> **Проверка.** http://localhost:3333 — девять типов документов с русскими
> названиями полей.

### Первые данные

Админка пустая, и сайт продолжит показывать демо-данные, пока в ней ничего нет.
Так задумано: репозиторий должен запускаться без ключей. Заведите минимум три
документа, чтобы увидеть настоящую связку:

1. **Сезон** — год 2026, статус «текущий», даты сентября.
2. **Площадку** — например, «Горка».
3. **Событие** — привязать к сезону и площадке, поставить дату и длительность.

> **Проверка.** На главной появилось ваше событие вместо демонстрационного.
> Если нет — подождите минуту: страницы пересобираются раз в 60 секунд.
>
> Если событие не появилось и через две минуты, проверьте статус сезона.
> Главная ищет сезон со статусом **«текущий»**; при любом другом она честно
> откатывается на демо-данные целиком, а не показывает половину настоящих.

## Шаг 2. Репозиторий на GitHub

```bash
cd /Users/diidentikit/otherworldly && git init && git add . && git commit -m "Сайт фестиваля: Next.js + Sanity"
```

Создайте пустой репозиторий на GitHub — **без** README и .gitignore, они уже есть —
и подключите, подставив своё имя пользователя:

```bash
cd /Users/diidentikit/otherworldly && git remote add origin https://github.com/ВАШ_ЛОГИН/otherworldly.git && git branch -M main && git push -u origin main
```

> **Проверка — важная, до пуша.** Убедитесь, что ключи не попали в коммит:
>
> ```bash
> cd /Users/diidentikit/otherworldly && git ls-files | grep -E '\.env\.local|\.dev\.vars'
> ```
>
> Команда должна не напечатать **ничего**. Если что-то нашлось — не пушьте,
> скажите мне, уберём из индекса до отправки.

Репозиторий можно сделать приватным: Cloudflare и GitHub Actions работают
с приватными так же.

## Шаг 3. Выложить сайт

Зарегистрируйтесь на **https://dash.cloudflare.com**. Воркер создастся сам
при первой выкладке — заранее ничего делать не нужно.

```bash
cd /Users/diidentikit/otherworldly/site && npx wrangler login
```

```bash
cd /Users/diidentikit/otherworldly/site && npm run deploy
```

Токен для этого не нужен: `wrangler login` авторизует через браузер.
Первая выкладка делается руками намеренно — так ошибки видно в своём терминале,
а не в чужом логе сборки.

> **Проверка.** Команда напечатает адрес вида
> `https://otherworldly.<поддомен>.workers.dev`. Откройте — должна открыться
> главная. Проверьте заодно `/en` и `/ru/timetable`.

> **Если упало с «exceeded the size limit»** — значит в сборку опять попала
> Студия. Убедитесь, что папки `src/app/studio` не существует.

## Шаг 4. Выложить админку

Отдельной командой, на хостинг Sanity:

```bash
cd /Users/diidentikit/otherworldly/site && npx sanity deploy
```

Адрес берётся из поля `studioHost` в `site/sanity.cli.ts` — сейчас там
`otherworldly`, то есть админка встанет на `otherworldly.sanity.studio`.

Эти поддомены общие для всех пользователей Sanity и раздаются по принципу
«кто первый». Если имя занято, команда откажется работать — тогда откройте
`sanity.cli.ts`, замените `studioHost` на своё (латиница, цифры, дефис)
и запустите команду ещё раз.

> **Проверка.** Откройте напечатанный адрес — админка просит войти,
> внутри те же документы, что вы завели локально.

CORS настраивать не нужно: сайт читает базу с сервера, а не из браузера,
а хостинг Sanity разрешён у себя по умолчанию.

## Шаг 5. Чтобы дальше собиралось само

Только теперь, когда сайт уже виден и работает.

### Токен Cloudflare

**My Profile → API Tokens → Create Token.** Наверху есть готовый шаблон
**«Edit Cloudflare Workers»** — если он в списке, берите его. Если Cloudflare
сразу открыл ручной сбор прав, отметьте две галочки:

| Группа | Право | Уровень |
|---|---|---|
| **Developer Platform** | Workers Scripts | **Edit** |
| **Account & Billing** | Account Settings | **Read** |

Первая — право выложить воркер. Вторая нужна wrangler, чтобы найти аккаунт;
без неё выкладка падает с невнятной ошибкой доступа, хотя по первой галочке
кажется, что прав достаточно.

Ниже, в **Account Resources**, выбрать свой аккаунт. **Zone Resources** не
трогать — они относятся к своему домену, а на `workers.dev` не участвуют.

Скопируйте токен сразу: второй раз он не показывается. **Account ID** — на
главной панели справа.

### Секреты репозитория

В GitHub: **Settings → Secrets and variables → Actions → New repository secret**.

| Имя | Значение |
|---|---|
| `CLOUDFLARE_API_TOKEN` | токен из предыдущего пункта |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID |
| `SANITY_PROJECT_ID` | Project ID из шага 1 |
| `SANITY_DATASET` | `production` |
| `SITE_URL` | адрес с `workers.dev`, полученный при выкладке |

Дальше каждый `git push` в `main` собирает и выкладывает **сайт**.
Админку это не трогает — она обновляется отдельно, командой `npx sanity deploy`,
и нужно это только когда меняются схемы документов.

## Шаг 6. Как обновляется содержимое

Отдельно настраивать ничего не нужно, и это стоит понимать до показа заказчику.

Кураторка публикует правку в админке — на сайте она появляется **в течение
минуты**. Каждая страница помнит, когда её собирали, и по истечении шестидесяти
секунд первый же посетитель получает свежую версию.

Вебхук, который обновлял бы страницу мгновенно, я намеренно **не** подключаю
на этом этапе. Он требует общего кэша в R2, иначе сброс подействует только
на один экземпляр воркера из нескольких — то есть будет работать через раз,
что хуже честной минуты ожидания. Оба шага описаны в конце.

> **Проверка.** Измените заголовок события, опубликуйте, подождите минуту.
> Если через две не изменилось — скорее всего, сборка идёт со старым
> `SANITY_PROJECT_ID`: сверьте секрет в GitHub с тем, что печатает
> `npx sanity projects list`.

## Шаг 7. Показать заказчику

Две ссылки:

- **сайт** — `https://otherworldly.<поддомен>.workers.dev`
- **админка** — `https://otherworldly.sanity.studio`

Пригласить кураторов можно из терминала:

```bash
cd /Users/diidentikit/otherworldly/site && npx sanity users invite имя@почта.ru -p ВАШ_ID --role editor
```

Роль `editor` — может писать и публиковать, но не может удалить проект.

**Бесплатный тариф Sanity включает трёх пользователей, а кураторов четверо.**
Это единственное место, где проект упирается в деньги раньше запуска. Решать
до того, как разошлёте приглашения, а не после.

### О чём предупредить честно

- Фотографии — заглушки. Настоящих съёмок у нас пока нет.
- Даты сентября 2026 — предположительные, ждём подтверждения.
- Кнопка билета показывает «скоро в продаже», пока нет аккаунта организатора
  на Timepad. Это состояние заложено специально, а не недоделка.
- Тексты в разделах «О фестивале» и «Опен-колл» — демонстрационные.
- Адрес `workers.dev` — временный, до покупки домена.

## Что дальше, когда сайт пойдёт в бой

**Свой домен.** Cloudflare → воркер → Settings → Domains & Routes. Домен надо
купить и направить на Cloudflare.

**Кэш в R2, и следом мгновенное обновление.** Сейчас пересобранная страница
живёт в памяти воркера и пропадает при перезапуске. Раскомментировать блок
`r2_buckets` в `wrangler.jsonc`, создать корзину, добавить `r2IncrementalCache`
в `open-next.config.ts`. К правам токена добавится **Workers R2 Storage → Edit**.

Под нагрузкой это заметно само по себе — то есть в дни фестиваля. Но главное,
что открывает общий кэш: только после него имеет смысл вебхук из Sanity
на `/api/revalidate` (маршрут уже написан). Без R2 сброс подействовал бы на один
экземпляр воркера из нескольких, и правка появлялась бы у одних посетителей
и не появлялась у других.

Порядок: сначала R2, потом вебхук. В обратном порядке получится механизм,
который работает через раз и о поломке которого никто не догадается.

**Timepad.** Завести аккаунт организатора, вписать `timepadEventId` у событий.
Кнопка переключится сама.

**Проверка уязвимостей.** `npm audit` показывает предупреждения в зависимостях
Sanity Studio. **Не запускайте `npm audit fix --force`** — он ставит несовместимые
мажорные версии и ломает сборку. Разбирать по одной, когда дойдут руки.
